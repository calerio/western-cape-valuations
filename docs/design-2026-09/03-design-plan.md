# Design plan — design & performance refresh 2026-09 (v1, 2026-09-23)

Status: wireframes and decisions 2–5 approved by the owner on 2026-09-23. Decision 6 (Graaff-Reinet only)
is **superseded** by the national renamed-places registry (research in progress; registry needs its own
approval before any override is applied). P0 integrity guards are done (`p0-integrity-guards`, merged here).
The Matzikama address hotfix is deployed from `main` and tracked separately. Production baseline stays the
immutable build `b-2b502178f94f`; nothing in this plan touches the linker, the builds or disposition semantics.

## 1. Principles
- Evolutionary: keep the three views, the token system, the data contract and every honesty rule.
- Fast: measurably lighter first load on all three pages; no new framework; no second map instance.
- Trustworthy: status is always text + glyph; required wording verbatim; raw evidence behind a disclosure.
- Civic, not corporate: editorial hierarchy, dense but calm; no gradients, glass, decorative cards or motion for
  its own sake (one type pairing, one palette, one reveal animation, plain backgrounds).
- Bilingual by construction: every new string is an i18n key with an AF entry; map labels localised where the
  tiles have Afrikaans, with graceful fallback; no invented translations.

## 2. Visual direction (refined with the frontend-design skill before implementation)
- **Type.** UI and numbers: IBM Plex Sans 400/500/600 (latin + latin-ext subsets, tabular figures). Display:
  Source Serif 4 600 for Explore headlines, section heads and the panel value (not for map labels). Both
  self-hosted as WOFF2 subsets under `assets/fonts/` with the OFL licence files, `font-display: swap`, size
  budget ≤ 120 KB total, `size-adjust` metrics on the fallbacks to cap layout shift. Map basemap labels keep
  the style's Noto glyphs.
- **Scale tokens** (new in `tokens.css`): type `--t-11 … --t-34` in rem; spacing `--s-1 (4 px) … --s-8 (48 px)`;
  radii unchanged; the dark block de-duplicated; status tokens `--st-ok`, `--st-warn`, `--st-neutral`,
  `--st-bad` each with an ink and a tint, used only with text + glyph.
- **Colour.** Keep the blue accent and the choropleth ramp; surfaces move to a warm off-white paper
  (`--bg2`) for Explore reading columns; chart marks use the existing category tokens.
- **Motion.** Explore: one staged reveal on first paint (opacity + 6 px translate, 60 ms stagger, ≤ 8 items).
  Panel: 160 ms slide/fade. Map: `fitBounds`/`easeTo` durations become 0 under `prefers-reduced-motion`;
  CSS transitions already clamp.
- **Backgrounds.** Flat surfaces, hairlines, a faint 8 px dot grid behind charts; no imagery, no gradients.

## 3. Information architecture and URLs
- `index.html` = Explore. Lands on the Western Cape level (province stats visible). Hash contract unchanged:
  `#m/<slug>`, `#d/<slug>`; no hash = province.
- `map.html` = the canonical map page (Map + Satellite). `plain.html` = thin compatible entry point serving the
  same page with the "map" basemap default; both keep `?db=`, `?nolink=1`, the hash, the stored language, the
  selected parcel and the camera. Hash extended: `#p/<place>|…&b=map|sat&c=<lng>,<lat>,<z>&s=<PRCL_KEY>`;
  existing `#p/…` forms still parse.
- View switcher carries context: Explore → Map passes the current municipality (`#m/<slug>` → camera fit);
  Map → Explore passes the municipality under the camera centre.
- Language: `localStorage['wcv-lang']` stays the source of truth; switching no longer reloads (UI re-applied
  in place, map labels re-expressed, open panel re-rendered from its last arguments).

## 4. Explore (index.html + atlas.js)
Data: `data/explore.json` (new, versioned, generated by `export_explore.py`; ≤ 60 KB raw) + existing
`stats.json`, `towns.json`, `rates.json`. The page never queries the search DB for aggregates; the search DB is
started only on search focus or after an idle pause, for address search.

| Section | Content | Source | Caveat shown |
|---|---|---|---|
| Headline | total value, valued properties, median, valuation-date span; "Find my property", "Open the map" | stats.json + explore.rolls | dates per municipality below |
| Locator | small SA outline (simplified, ~10 KB) + WC choropleth by municipality (navigation) | simplified geo | — |
| Coverage strip | rolls used, SVs, Cape Town cycle, Laingsburg draft, sectional units counted | explore.meta/rolls | link to details |
| Where the value sits | sortable table: municipality · properties · total (share bar) · median freehold-residential (marker on one scale) · date of valuation; first 8, "Show all 25" | stats.json + explore.pct/dates | comparison only, no trend |
| How values are spread | log histogram (22 bins) with p10/p50/p90 and the middle-50% band; top-10% and bottom-50% callouts | explore.loghist/pct/conc | concentration is of valuations, not wealth |
| What the roll contains | one stacked 8-group bar + legend | explore.groups | "7 rolls have no vacant category" |
| When each municipality valued | dot chart on a 2018–2026 date axis | explore.dates | date of valuation, not a trend |
| Notable findings | 3–6 statement cards with "query ▸" | explore.findings + queries | per-m² only under the reliability rule |
| Footer | MPRA basis, explainer, municipality index | static | — |

Municipality level: same structure (choropleth zooms, table becomes towns/suburbs from towns.json, plus the
existing "Who sets & governs these values", rates and provenance blocks). Progressive disclosure: sections after
the first two render collapsed on mobile and expand on demand; charts render when opened. Exclusions (Cape Town
holding/allocation duplicates; land fields where the rule fails) are shown as footnotes drawn from
`explore.meta.caveats`, and the displayed totals reconcile with the stated statistical universe (a reconciliation
test in the export asserts this).

Fixes folded in: hover tooltip (B3), hard-coded year (B4; the cycle comes from stats.json provenance), money
formatting unified with the map (`R1.25 m` / `R850 000` style, AF words), mobile header, aria labels, EN/AF for
"Top 10/20/30".

## 5. Map page (map.html/plain.html + assets/map/*)
Module split (ES modules, cache-busted imports): `map/main.js` (boot, chrome, hash, language), `map/style.js`
(basemap: fetch Liberty once, transform, basemap switch, label expressions), `map/parcels.js` (cadastre fetch,
click, overlap chooser), `map/panel.js` (states, badges, disclosure, list/detail renderers), `evidence.js`
(code → plain language), `selection.js` (existing), CSS in `assets/map.css`. Preserved test surface:
`window._map`, `window._integrity`, source `parcels`, layer `parcels-fill`, `#pbody`, `#maphint`, EN substrings.

Basemap: the Liberty style JSON is fetched by the page and passed as an object after a pure transform
(`transformStyle(style, {lang, basemap, overrides})`, unit-tested):
- adds the Esri raster source + layer directly above `background` (visible only in `sat`);
- in `sat`, hides landuse/landcover/water/building/road-fill layers, keeps boundaries and all symbol layers with
  a dark halo (`text-halo-color` dark, width 1.5) and lighter parcel casing;
- reduces POI clutter at z ≥ 16 (parking/minor POI classes filtered; `poi_r20` from z18);
- rewrites `text-field` of every symbol layer that reads `name` (23 layers) to
  `["case", <renamed-place overrides…>, ["coalesce", ["get","name:af"] (AF only), <original expression>]]`;
- ward labels off by default (chip), `Ward` string localised.
Switching basemap or language mutates layer visibility/layout only (no `setStyle`, no reload).

Renamed places (after registry approval): a compact `data/geo/renamed-places/registry.v1.json` loaded once;
overrides keyed on identifiers present in the tiles (tile feature id verified against the tile snapshot, with
class + exact current-name + province bbox as the scoped fallback and a build-time uniqueness check); never a
global text replacement; only settlement `place` features; a discreet "The map shows selected established place
names" note (EN/AF) in the attribution popover; both names searchable in place search with the official name
kept in the result details.

Parcel styling: thinner, lighter outlines; selection outline colour + dash pattern follow the status.

## 6. Result panel states
| decision | badge | heading / sub (verbatim where asserted) | body |
|---|---|---|---|
| accepted_high | ✓ Verified | address; "municipal market value" | detail rows, rates, note; disclosure "Verified link: …" + codes |
| accepted_group | ✓ Verified property group · sectional scheme | "Erf n — k valuations"; "k sectional-title units on this parcel" | sum only when complete, labelled as a sum; list |
| review | ? Possible match | "possible match — town not confirmed" | list; plain-language why |
| ambiguous | ≡ Several entries fit | "Erf n — several entries fit"; "unverified — same erf number, with some locality or area evidence" | candidates; rejected note |
| not_in_roll | ⊘ No valuation found | "No valuation found" | coverage note |
| abstain | ⚠ Could not link | "Could not link this parcel to the roll" | unverified candidates if any |
| missing | ⊘ Not in this data build | "Not in this data build" | — |
| unavailable / integrity | ⚠ Valuation data unavailable / Data build could not be verified | existing strings | retry hint |
| loading | … | "Looking up valuation…" | skeleton |
Evidence: `evidence.js` maps the 26 linker codes (from `evidence-codes.json`) to EN/AF sentences shown under
"Why this result?", with the raw codes in monospace inside the disclosure. Panel is `role="dialog"` with a
labelled heading, `aria-live="polite"` status line, focus moved in on open and back to the map on close/Escape.
Mobile: bottom sheet with peek (badge, address, value) and expanded states; attribution collapses to a button
that never sits under the sheet.

## 7. Accessibility and keyboard
h1 + landmarks on every page; skip link; Explore municipality table rows and choropleth shapes keyboard-reachable
(`role="button"`, labels); language toggle as real buttons; 44 px targets; contrast ≥ 4.5:1 for text over
platters (opaque panel on Satellite); focus-visible ring retained; reduced-motion covers MapLibre easing.

## 8. Performance targets (baseline in `00-audit.md` §4)
| Metric (cold, fast link) | Baseline | Target |
|---|---|---|
| Explore transferred at first usable | 2.6 MB | ≤ 0.9 MB (DB deferred, geo simplified, fonts ≤ 120 KB) |
| Explore first usable (desktop) | 0.68 s | ≤ 0.6 s; province stats visible without a click |
| Map transferred at style ready | 4.9 MB | ≤ 2.4 MB (DB deferred, Natural-Earth raster removed at low zoom or kept at half the tiles, GeoJSON simplified) |
| Satellite imagery | loaded at boot | only when Satellite is chosen |
| Click → panel | 0.32–0.65 s | unchanged or better |
| Basemap switch | page reload (≥ 1 s) | ≤ 150 ms, no reload |
| Language switch | page reload | ≤ 300 ms, no reload |
| Console | 2 sql.js warnings + sprite warnings | no errors; warnings from our code = 0 |
Means: `defer` on vendor scripts pinned to exact versions with SRI; search-DB pre-warm after first paint via
`requestIdleCallback` (DATA_CONTRACT §11 pre-warm kept, timing changed); `preconnect` only to Supabase and
OpenFreeMap (measured); simplified GeoJSON generated by the export; imagery source added lazily; no
backdrop-filter over the map canvas on mobile; immutable `?v=` assets keep the existing cache pattern.

## 9. Tests
Unit (`node --test tests/`): style transform (AF expression, override expression, satellite layer sets, POI
filter), registry loader + uniqueness, evidence dictionary completeness (every code has EN + AF), money
formatting parity EN/AF, selection guard (existing). Browser (`tests/browser/*.js`, Playwright WebKit):
Afrikaans label switching (Mossel Bay → Mosselbaai; fallback where `name:af` is missing), renamed-place
overrides (representative entries per province, both languages, both basemaps, z7–z12, no duplicate labels),
Map ↔ Satellite transition (single instance, camera + selection kept, imagery requests only after switch), every
disposition panel (fixture parcels per decision), loading / unavailable / integrity states (route blocking),
mobile navigation (390 px: sheet peek/expand, no horizontal overflow, controls ≤ 25%), Explore landing, drill,
search. The smoke matrix runs unchanged. An i18n completeness script fails the build on a missing AF entry.

## 10. Delivery and rollback
Preview on the design worktree (`http://127.0.0.1:8766/`). Before requesting deployment: final screenshots
(3 views × desktop/mobile × EN/AF), before/after perf under the same conditions, browser results (Safari/WebKit
automated; Chrome and Firefox opened for the owner's manual check), smoke results, known limitations
(Afrikaans label coverage measured from tiles; registry coverage), and the exact procedure: merge
`design-2026-09` → `main`, push; rollback = `git revert -m 1 <merge>` (assets and generated files only; the DB
build and Supabase namespaces are untouched).

## 11. Out of scope / risks
Data fixes beyond exports (Cape Town double count stays in the DB and is excluded from Explore aggregates; the
Matzikama pipeline is its own track); registry contents until approved; font licences (OFL, files vendored with
licence text); WebKit-only automated browser coverage.
